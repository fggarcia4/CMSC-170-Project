Predicting a project’s budget tier (low, middle or high) using specific inputs from the dataset, using Naive Bayes and a multiclass Perceptron.

Rembulat, FrancineLeader Garcia, FredmarcMember

Problem statement and motivation

The problem is to predict a project’s budget tier (low, middle or high) with just using specific inputs from the dataset.

Infrastructure projects differ widely in cost, and reviewing tens of thousands of them by hand is impractical. We want to know whether a project’s budget tier can be predicted from basic details such as its category, location, contractor and source of funds. A reliable prediction could support early budget estimation and help flag projects whose budgets look unusual. This project also lets us compare two classification methods, Naive Bayes and a multiclass Perceptron, on a large real-world dataset of DPWH infrastructure projects.

Preprocessing steps

We restricted the data to 2023–2025, cleaned the projects (82,617 down to 76,232) and dropped uninformative columns. For the Perceptron, features are also standardized and a bias term is added.

Methods

Naive Bayes

Naive Bayes is a probability-based classifier. For each tier it estimates how likely the tier is overall and how likely each input value (such as a category, province or contractor) is within that tier. It assumes the features are independent of one another given the tier, multiplies these probabilities for a new project, and predicts the tier with the highest result. This suits our data well because most inputs are categorical.

Perceptron

The multiclass Perceptron keeps one neuron per tier. Each neuron learns a set of weights, scores a project as the weighted sum of its standardized features plus a bias, and the tier with the highest score is the prediction.

Experimental setup

Data splits

We used an 80 (training)/20 (test) split, taking 80% of each tier for training and 20% of each tier for testing so that tier proportions stay the same. Choosing a 20% test size ensures our evaluation is reliable without starving the model of training examples.

Metrics

Accuracy, Macro-F1 (the average F1 across tiers, built from per-tier precision and recall) and the off-by-two rate (low projects predicted as high, or high as low). Higher is better for the first two; lower is better for the off-by-two rate.

Hyperparameters

Because Perceptron accuracy was low, we tried five learning rates (0.01, 0.05, 0.1, 0.2 and 0.5), from small to relatively large, to see how step size affects convergence, classification performance and training time. We used 0.1 as the baseline, and every rate gave results similar to it.

Discussion

Why the methods performed as they did

Naive Bayes consistently outperformed the Perceptron on correct predictions, Macro-F1, accuracy, and off-by-two rate. The difference may come from how each method uses the input features.

Naive Bayes works fromt he probability of each input given a tier, which suits a dataset with many categorical features. The Perceptron on the otherhand needs these converted into numers first, which can add noise and make some features count more than others.

The Perceptron also learns weights to separate the tiers, this is harder when the tiers overlap or when the relationship between the input and the tier is more complex. Naive Bayes does not have this problem, since it only needs to count how often each value appears in each tier.

However, this doesn't mean Naive Bayes is better than Perceptron in general, each method suits different kind of problems like how Naive Bayes suits our project better than Perceptron. Naive Bayes is better on projets where the data has many categorical or word-based features. Perceptron may work well with tasks with mostly numeric features and datasets where it has enough examples to learn good weights.

Limitations

Only eight of the twenty-four columns could be used for prediction, some of the remaining columns were vague, which made them less useful for telling the tiers apart during training.

Some columns, such as contractor, had many different values that rarely repeated. This gives the models little to learn from, since a value seen once or twice says a little about the tier.

Lastly, the algorithms implemented for this project were only limited to Naive Bayes and Perceptron, other algorithms might have worked better on this dataset.

Possible improvements

The project was limited to approaches introduced in the course, so other supervised classification algorithms were not explored. Variants of Naive Bayes and the Perceptron, in how they predict and compute, could also be tried.

Conclusion

This project implemented Naive Bayes and a multiclass Perceptron to classify DPWH infrastructure projects into low, middle and high budget tiers using eight project characteristics. Naive Bayes performed better across every reported metric: it reached 68.98% accuracy and a 0.6619 Macro-F1, and made fewer serious classification errors. Its probability-based approach appears better suited to these categorical features.

Even so, accurately classifying project budgets remains challenging, because the selected features may not capture every factor that influences project cost. The project still shows how machine learning can be applied to DPWH infrastructure data to sort projects into budget ranges.
